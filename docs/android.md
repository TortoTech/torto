# Android：Rust core + Kotlin

Android 已纳入 `torto` workspace；独立的 `torto-app` Flutter 仓库仅作为功能与交互参考。本次不迁移旧 App 的本地数据库、缓存、配置和密钥，也不保留 Dart/Flutter 桥接层。桌面端的现有文件名、同步协议和凭据标识保持兼容。

## 边界

```text
apps/desktop (egui / winit)       apps/android (Kotlin / Compose)
          │                               │
          │                    crates/android-bridge (UniFFI)
          └──────────────┬────────────────┘
                  crates/app-core
         library / search / AI / translation / fonts
         WebDAV / annotations / statistics / persistence
                         │
       formats → publication → layout → reader → renderer
```

- `app-core` 不依赖 egui、winit、JNI 或 Android。桌面端保留薄的 re-export，实际实现只有一份。`reading::ReadingPipeline` 统一 rewrite → translation → semantic layout → paragraph structure 的组合顺序。
- 宿主在首次服务调用前指定数据、配置、缓存目录，并安装 `SecretStore`。当前一个进程只允许一个 profile；重复初始化相同路径可用，更换 profile 会明确失败。
- Windows、macOS 和 Android 共用 Rust `FileStore`，API Key 和 WebDAV 密码以明文保存到配置目录的 `credentials.json`，不进入书库云同步、诊断导出或公开设置 DTO。Android 文件位于应用私有目录，禁止应用备份；显式 smoke profile 使用独立内存凭据。
- UniFFI 只传书籍、目录、位置、文本区域、结果和命令。文字位置由 Rust 管理，不将 Kotlin 的 UTF-16 索引当成原文偏移。
- 页面用共享 CPU 渲染器绘制，通过手写 JNI 接口复制到 `Bitmap`。滚动专注保留包含屏幕外内容的正文条带；相邻位置复用像素及 Bitmap，仅传递新的位置、焦点和选择信息。注册表保存弱引用并验证帧 ID、尺寸、像素格式和 stride；不把裸指针或整页 RGBA 字节数组放进 Kotlin DTO。
- `MobilePage.close()` 释放帧引用；专注条带的共享像素由阅读会话保留，失效、内存通知或关闭时释放。条带最多三屏，原生像素和 Android Bitmap 各限制在 24 MiB；超大视口保留原有单屏软预算例外。切换缓存时动画最多额外保留一张旧 Bitmap，结束即释放。阅读会话显式 shutdown/close；ViewModel 跨旋转保留，关闭时后台释放。所有解析、数据库、网络和绘制在 worker 上运行。
- UI 命令串行，切书时递增 generation，旧结果不回写。取消 Kotlin 协程不等于取消阻塞 Rust 工作，因此 native 调用完成前不会提前释放串行锁。
- 阅读缓存默认 24 MiB layout + 48 MiB raster，内存通知后缩减到 4/8 MiB 并停止预取；当前可见页允许超过软预算。桌面端默认预算不变。页面仅在内容或选择变化时重绘。

## 三端凭据存储

Windows、macOS 和 Android 的 AI 提供商、搜索、OCR 与 WebDAV 凭据共用 `crates/app-core/src/credentials/file.rs`。JSON 文件按 service/account 区分条目，文件锁和进程内互斥保护读改写（Android 使用 rustix 的非阻塞 flock，避开 Rust 1.97 标准库不支持 Android 文件锁的情况），原子替换后回读校验。Unix 文件权限为 `0600`；最多 2 MiB、512 条，每项最多 128 KiB。普通配置仍与凭据分开，设置 DTO 只返回“已保存”状态，空输入保留原 Key，日志和诊断不包含凭据内容。

首次使用时完整迁移旧存储，然后再接受新写入。桌面端读取旧加密库及配置引用的旧系统条目；macOS 这一次仍可能需要钥匙串授权。Android 一次性解密旧 preferences，先保留其原账户哈希，首次访问时改为统一的 service/account 标识。原子写入并验证成功后才移除旧加密文件或 preferences；失败保留旧数据并等待显式重试。已存在的明文文件始终优先，不重新导入已删除的旧 Key。后续读写不再调用 Keychain、Credential Manager 或 Android Keystore；兼容代码仅用于迁移。

Android 路径为 `files/core/config/credentials.json`，不暴露给 FileProvider。Windows 便携版路径为 `Data/config/credentials.json`，凭据可随目录跨电脑携带；见 [便携版](windows-portable.md)。单元测试使用内存模拟旧系统存储，不访问个人凭据。

当前凭据与便携版验证：完整 workspace 1,893 项通过、0 失败、132 项按原配置忽略；Android API 36 ARM64 模拟器的 6 项凭据／AI 设置／云同步／诊断测试通过。Windows x64 生产构建及测试目标交叉编译通过，PE 导入未发现独立 MSVC 运行库依赖；真实 Windows 启动和更新回滚由新增 CI 脚本验证，本机未代替执行。

## 已接通的 Android 功能

- 界面使用中性配色：浅色背景 `#F4F5F7`、白色卡片与深灰文字，品牌控件为 `#07C160`，浅色文字强调色 `#078A46`、深色强调色 `#36DA83`；深色使用中性黑灰层次，补齐 Material 全部容器、反色和 fixed 色值，避免默认紫色残留。开关、选中图标、输入控件、菜单和原生选择标识统一使用绿色系，启动窗口提供对应日／夜配色
- 系统页以两行分组入口显示深色模式（跟随系统／未开启／已开启）和界面语言（跟随系统／中文／English），右侧状态及箭头进入独立配置页；配置页采用居中标题、跟随系统开关和手动勾选列表，启用跟随后收起手动列表，切换即时保存。AI 排版、翻译与阅读助手配置不再提供管理提供商入口或保存按钮，返回／关闭子页时保存当前页修改
- 设置页与阅读设置弹窗共用分组卡片：同组项目共用浅色白底／深色深灰底，页面及卡片内边距各 16dp，组间距 12dp、圆角 16dp；居中页标题和设置项标题均为 16sp，右侧所选值为 14sp，18dp 箭头统一靠右。长名称最多两行并在选择弹窗显示完整内容；说明位于组外，字号等滑杆数值与标题同行。覆盖首页、系统／外观／语言、排版、三类 AI 配置、提供商编辑、云同步和关于
- 系统文件选择器导入，三列封面书架（无最近阅读边框）、长按删除确认，格式解析与桌面共用
- 手机阅读源过滤 `body` 自身的 CSS `margin`（含简写、逻辑方向、百分比和 `!important`），保留 `padding`、内部元素边距和源定位；非统一版式因此只使用应用页框和内部排版，统一版式继续沿用既有规范化。应用页框统一为左右 20dp、上下 16dp，默认桌面解析保留原书边距，PDF 原图不经过过滤
- 阅读、翻页、目录、全书搜索与源位置跳转、长按选择/复制，支持自由/单词/句子/段落粒度
- 翻页／翻节使用独立完成序号确认请求结束，不依赖页面或位图发生变化。到书末继续向后翻时，即使返回相同页面也会释放手势等待状态并复位横向位移；普通控件刷新不提前确认仍在执行的导航，失败和书籍切换也不会遗留等待锁，继续复用原有像素缓存
- 笔记面板使用居中 16sp 标题、书籍摘要与“搜索笔记”入口，高亮为原文卡片，批注为笔记正文加灰色引用卡片，列表不提供编辑／删除按钮。按共享阅读核心解析出的章节归属分组，并按正文顺序排序，支持同一 XHTML 内多个章节；批量解析只准备含笔记的小节，不改变阅读位置或进行分页。搜索共用“搜本书”的输入栏，匹配划线原文及批注内容，保留章节分组，点击结果跳回对应源位置
- 从列表或搜索结果定位笔记后进入独立查看状态：顶部浮动栏显示“笔记”、章节名、返回列表菜单和退出按钮，底部为笔记列表／上一条／下一条，首尾禁用越界操作；两个列表入口均返回原笔记面板。工具栏固定叠加，不改正文视口、不显示普通阅读悬浮动作或跳转进度条；切换书籍及退出时清除查看状态，过期跳转不能重新打开该状态
- 笔记查看工具栏使用约 40dp 的紧凑背景（大字号下自适应增高），标题仍为 16sp，章节为 11sp；头部菜单／关闭图标实际为 20／18dp，底部图标为 18dp、标签为 10sp／12sp 行高，操作间用细竖线分隔。背景外的透明点击区域仍至少 48dp，普通阅读图标保持原尺寸
- 字号、中日韩／拉丁书籍的主字体与混排字体、代码字体、统一版式、深色阅读与本地设置保存；助手代码跟随阅读代码字体，不内置重复字体。代码字体、字号集中在“通用”分组；手机端不提供字重配置；排版面板移除重复标题，仅通过箭头行进入 AI 排版详情，设置首页不再重复提供 AI 排版入口。翻译配置通过通用设置进入；阅读页排版面板不再提供“AI 排版本页”或“标记为读完”操作
- 稳定阅读位置写入共享 SyncStore，关闭/重新打开及横竖屏重排后恢复；进入专注模式继续使用保存的精确源位置，避免退回所在页的首段，失效源位置仍按共享 locator 规则回退
- 进度、批注、同步快照、时钟与书籍状态的 SQLite 写事务共用 `BEGIN IMMEDIATE`：先取得写入资格，再读取并修改，避免 WAL 下先读后写升级导致的 `SQLITE_BUSY`／`SQLITE_BUSY_SNAPSHOT`。保留 5 秒有界等待和只读并发，事务不跨网络操作；Android 记录脱敏的数据库锁错误操作类别，便于诊断
- WebDAV 手动／前台／后台自动同步书籍、阅读进度、注释和统计；共享 7 种云盘预设，支持设备名称及前台／后台独立开关，导入／删除书籍后合并触发同步
- AI 提供商页通过头部右侧加号图标新增，列表不再显示添加文字按钮；支持提供商增删改、类型预设、模型刷新图标／搜索／手动添加及各用途独立的模型、思考等级；Key 只进入独立凭据文件，设置返回值仅带“已保存”状态，空输入保留原 Key，不提供单独清除已保存 Key 的入口
- 本页语义排版及翻译；请求队列、优先级、并发、固定批次、超时与抢占共用 Rust 核心，Kotlin 仅上报阅读需求和交互状态。同时启用时先识别原文结构，再翻译并整批发布；图表／公式备注和目录翻译独立调度，后台预取只预热当前目录单元的结构。模型等待不持有阅读会话锁，预取不移动阅读位置。基础识别结果共用核心的局部分组／指纹安装，重复识别保留已经完成的增强。翻译、排版、目录翻译与预处理不显示头部进度条或通用忙碌进度条，阅读头部不提供 AI 停止／暂停入口；翻译沿用共享核心的首轮加一次重试，最终错误统一以“翻译服务错误”轻提示显示 2 秒，无常驻重试／设置入口；后台取消仍然生效。详见[阅读 AI 请求调度](reading-ai.md)
- 统一版式启用共享优化断行、英文断词及内联引用呈现；按句分段后逐句使用同一优化器，保留强制句间换行、桌面端首句字形位置／缩进及公式、脚注归属。选中断词后可重新塑形并再次计算断行，内部零尺寸标记不计作正文对象，不触发整段回退。恢复已缓存的手动 AI 排版与关闭自动调用模型分开控制，按原文、模型、端点和语言校验。显示范围缓存每节最多 128 份、读取文件限制 4 MiB，内存最多保留 16 节
- 脚注与网页标识共用桌面的浅／深色蓝色强调色及原有几何，打开脚注时在原标识下保留短横线，关闭后移除。脚注弹窗仅显示融入第一行的编号和原生富文本正文，间距为 0.3em、后续行占满宽度，不显示标题、关闭按钮或查看原文位置按钮；通过下滑、点击外部或系统返回关闭，短注释按内容收缩，长注释滚动。图表／公式引用共用桌面定位、原始链接优先和歧义规则，打开原生预览；索引在后台构建，预算 2 MiB，不解码全书图片。表格保留整表来源，支持正文与预览中的表格／图表切换；公式备注默认收起，切换只复用目标语言结果，不调用模型
- 原文／双语展示、目标语言、目录翻译与专家翻译；翻译开关跨会话保存。正文和目录请求共用按书籍／目标语言保存的专家术语表，复用桌面的提示词、术语校验、缓存与短 key 协议
- 表格图表和公式备注复用共享增强服务，以原文及识别结果为依据，输出使用翻译目标语言，公式备注默认收起。增强请求不持有阅读会话锁或 Kotlin 操作互斥锁，不阻塞基础正文显示；可见来源优先，单个工作请求最多 180 秒。增强准备队列最多 32 项、估算输入预算 8 MiB，完成记录最多 256 项；导航和手势暂停准入，已发送请求按核心抢占规则处理；切换配置、后台及停止取消旧请求。中断的有效任务重新入队，模型／端点／语言或原文变化后拒绝旧结果；弹窗或选区时延后正文刷新，关闭后继续，离屏结果只更新缓存。UI 不绘制额外进度条，增强失败保留基础正文
- 图表及公式备注的 SVG 文字共用布局核心的字体数据库；Android 在工作线程首次初始化时显式扫描系统字体目录，并设置 Roboto／Noto Serif／Roboto Mono 通用族，补足 fontdb 在 Android 上未实现的系统字体发现。字体数据库跨布局与 SVG 工作者共享，不逐帧扫描，不增加内置字体文件
- 书架首帧显示后，在后台自动下载缺失的默认字体；与桌面端复用 Rust 下载批次、缓存校验、重试和镜像回退，优先下载较小的拉丁字体。字体来自 lab Release 的 GitHub Asset API，活动重建和手动点击共用同一任务，不占用阅读操作锁，也不显示头部进度条。失败时继续使用系统字体，下次启动或在排版设置中重试；下载完成后提示“新字体已下载完成”，当前书籍需要更新时提示右侧提供“应用”，5 秒后自动消失，活动重建不重置期限。也可通过排版设置中的“应用已下载字体”保留位置重排，不在滑动中自动改变版面
- 沿用旧 App 的米白/棕色与深色主题；首页“书架 / 我”导航内容区为 56 dp，系统安全区单独计算，大字号允许自然增高。阅读 footer 保留五个入口，AI 助手／当前段落按句分段／翻译从左到右悬浮于右下角，统一使用 48 dp 深色圆形与白色图标，随 footer 渐显／渐隐；面板打开时隐藏悬浮按钮及 header，保留 footer 可点击切换；header 底部与 footer 顶部使用同样的细分隔线。进入书籍默认隐藏工具栏，阅读手势、文字选择与跳转收起工具栏；普通模式点击中间 60% 区域、专注模式点击当前块切换显隐。隐藏工具栏不改变原生阅读视口，阅读页不显示底部进度与章节信息
- 正文使用完整安全视口，仅避让挖孔与系统导航安全区，不再固定预留上下工具栏高度；工具栏覆盖正文，顶部状态栏随 header 显隐，退出阅读后恢复系统栏。专注模式固定纵向滚动与统一版式，单独保留经典模式的原书／统一偏好；按句分段和专注样式仅在专注模式显示，不再提供滚动／分页专注切换，旧版保存的关闭滚动配置也不再生效
- 经典模式支持左右跟手预览、松手确认／回弹及有限缓动。专注横向翻节沿用旧 App 的双页平移、松手确认 140 ms／取消 150 ms 缓动；预览未准备好时先回稳再导航，不滑出空白页。相邻页／小节由 Rust 在后台绘制；专注预览仅保留目标视口，恢复当前源位置和滚动条带，不写阅读进度。同一阅读单元内复用预览，后台准备在两次调用之间让出串行队列；Android 仅保留前后各一张位图（合计上限 24 MiB），拖动不请求重新排版。长块的中间停靠点优先对齐文字行起点
- 专注模式横向手势切换相邻目录阅读单元，同一 XHTML 内的小节分别处理；纵向继续逐块拖动。专注拖动在本地复用条带像素；方向锁定后扣除触摸阈值，块边界使用有界软阻力，松手前采样速度并用临界阻尼弹簧收敛到块位置，保留可中断／接续时的速度。短块的确认距离取相邻停靠距离的一半，限制在 8–36dp；越界余量不超过相邻停靠距离的四分之一及原有 64dp 上限，真实节边界保留原有阻力与确认距离，反向甩手取消当前拖动。原生确认相同停靠点不重新启动缓动，快速接续手势在待确认期间仍跟手，最多暂存一次后续翻块；新位图复制完成后在 worker 调用 `prepareToDraw()`，空闲时停止绘制

## 本机构建

前置：仓库固定 Rust toolchain、JDK 17、Android SDK 36、NDK `28.2.13676358`、`cargo-ndk 4.1.2`。

Linux 构建宿主还需安装 `pkg-config` 和 `libfontconfig1-dev`（Debian／Ubuntu）；它们供宿主上的 UniFFI 生成器使用，不进入 Android 安装包。

```sh
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk --version 4.1.2 --locked
sdkmanager 'platforms;android-36' 'build-tools;36.0.0' 'ndk;28.2.13676358'
export ANDROID_HOME=/path/to/android/sdk
export JAVA_HOME=/path/to/jdk17
cd apps/android
./gradlew :app:assembleDebug
# 分别生成 ARM64 和 x86_64 APK，不生成通用包
./gradlew :app:assembleDebug -PrustAbis=arm64-v8a,x86_64
./gradlew :app:assembleDebugAndroidTest
./gradlew :app:connectedDebugAndroidTest
./gradlew :app:assembleRelease
```

默认仅 ARM64；可用 `-PrustAbis=arm64-v8a,x86_64` 同时构建，分别生成 `app-arm64-v8a-{variant}.apk` 与 `app-x86_64-{variant}.apk`（未签名 Release 文件名额外带 `-unsigned`），每个 APK 只含一种架构。当前不提供 32 位 ARM／x86。最低 Android 8 / API 26，target/compile API 36。调试包 `org.tortotech.torto.debug`，正式包 `org.tortotech.torto`，数据和凭据文件隔离。旧 App 不被替换或清理。

Gradle 自动调用 `scripts/build-android.py`，每个 variant 分别生成 `.so` 与 Kotlin binding；绑定读取本次 Android `.so` 的元数据，不依赖手工维护 JNI 方法清单。生成文件不提交。修改核心后不要跳过原生构建任务。

Release 使用 Rust release profile，保留独立 `.dbg` 后剥离库符号，R8 mapping 另存。启用 R8 与未使用资源收缩，仅保留界面支持的中文／英文语言资源。Android 链接使用兼容 API 23 起的 APS2 重定位压缩及 safe ICF，保留异常展开与恢复；ELF 继续按 16 KiB 对齐。签名通过以下环境变量提供，缺少时生成 unsigned APK，绝不回退使用 debug key：

- `TORTO_ANDROID_KEYSTORE`
- `TORTO_ANDROID_STORE_PASSWORD`
- `TORTO_ANDROID_KEY_ALIAS`
- `TORTO_ANDROID_KEY_PASSWORD`

APK：`apps/android/app/build/outputs/apk/`；Rust 符号：`apps/android/app/build/generated/rust/release/symbols/`。`.github/workflows/android.yml` 在 PR/main 构建 debug/device-test APK 与 unsigned release，仅保存 Actions 产物。稳定版本 tag 构建独立的 ARM64／x86_64 正式签名 APK；也可手动填写 `release_tag`，严格检出该 tag 对应提交。

正式签名需要在 `TortoTech/torto` 仓库配置 `ANDROID_KEYSTORE_BASE64`、`ANDROID_STORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`，复用旧 `torto-app` 的证书。证书／密码只在签名步骤注入，临时证书随步骤清理，不进入产物。`scripts/package-android-release.py` 校验实际包名、版本、非 debuggable、正式证书 SHA-256、单架构和 16 KiB 对齐，生成 `Torto-{version}-android-{abi}.apk` 及 `.sha256`。证书指纹固定为旧正式证书的公开指纹；更换证书需单独设计升级兼容方案。

独立发布任务只向已发布、标题与 tag 一致的稳定 GitHub Release 附加 APK／校验文件，沿用现有更新说明；不自动创建 Release。同名相同内容可重试，同名内容不同则拒绝覆盖，需发布新版本。签名缺失或校验失败不会发布 unsigned APK。符号、R8 mapping 和测试 APK 留在 Actions，不加入 Release。Android 工作流成功后触发现有 Gitee 镜像，手动 tag 构建显式触发同步；一旦 Release 出现 Android APK，镜像要求两个架构及校验文件全部齐备，验证所有远端附件后再写入各架构更新清单。旧版无 APK 的 Release 仍可镜像。

## APK 体积与打包方式

默认将原生库以未压缩形式放入 APK，供 Android 直接映射，避免安装后保留第二份原生库。GitHub／Gitee 直接分发时，可显式选择压缩 APK：

```sh
./gradlew :app:assembleRelease -PcompressNativeLibraries=true
```

压缩方式保留全部功能，但安装时需解压原生库，安装后占用会增加；不是引擎本身体积降到压缩后的大小。两种方式均保留原生库 16 KiB ELF 对齐（[Android 说明](https://developer.android.com/guide/practices/page-sizes)）。默认不改变现有安装方式。

当前 Release 实测（未签名）：

| ABI | 常规 APK | 压缩 APK |
| --- | ---: | ---: |
| arm64-v8a | 39.24 MiB | 19.36 MiB |
| x86_64 | 45.12 MiB | 20.79 MiB |

ARM64 优化前为 41.27 MiB；原生库重定位数据及资源实际减少约 2.03 MiB，其余差异来自打包压缩。压缩版安装后总占用比常规版约增加 17.6 MiB，不把它算作运行时内存下降。

用优化后的生产原生库在独立预览包验证，不需要正式签名：

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest -PreleaseNativePreview=true
# 验证压缩库的安装／加载
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest -PreleaseNativePreview=true -PcompressNativeLibraries=true
```

此选项只将 Debug 的原生库与绑定切到 Release 产物；预览包名、凭据文件与数据仍保持隔离。关闭该选项后，普通 Debug 构建继续使用调试原生库。

## 验证

```sh
cargo test --locked --workspace
python3 scripts/check-android-alignment.py apps/android/app/build/outputs/apk/release/app-release-unsigned.apk
```

对齐检查要求每个 APK 只含一种受支持的 ABI，核对 ELF 实际架构及每个 `.so`（含 JNA 和 AndroidX）的 ELF LOAD 16 KiB 对齐；未压缩库还需核验 ZIP 起始位置的 16 KiB 对齐。压缩库由系统安装时解压，不适用 ZIP mmap 对齐要求。Debug 与 Release 使用不同输出目录，切换 ABI 时清理旧生成结果。

Rust bridge 回归覆盖导入去重、搜索定位、绘制、选择、批注增删改和重排定位、统计、流式助手与取消、工具修改确认/放弃、原图/公式预览、脚注、链接历史、专注切换、取消 AI 处理、跨会话离线译文缓存及模型切换、帧释放和关闭后调用；reader 回归覆盖移动缓存策略在刷新后的保留。Android instrumentation 覆盖实际 JNI Bitmap 复制、错误帧/尺寸拒绝、阅读重排与位置恢复，以及旧 Keystore 迁移、明文凭据与账户隔离。测试不调用付费模型、不使用个人 WebDAV 账户。

## 读完页

最后一页继续向后翻，或专注模式在最后一节继续向后翻节，会进入独立的“全书完”页。进入不自动标记；点击“标记读完”后才保存状态并显示“已读完”和累计读完本数。页面包含本书阅读时长、天数、笔记数、最近阅读明细及底部“退出阅读”，不包含分享、推荐或点评。

向前翻回时直接显示原先保留的正文、页码及焦点，不再额外调用原生上一页／上一节。普通翻页即使原生返回完全相同的帧，也通过独立完成计数释放手势锁，避免末页卡死。书籍切换丢弃旧统计任务；重复进入和重复标记不追加已读完事件。

当前验证：API 36 ARM64 模拟器通过手动标记／重复进入／精确返回／退出书架的完整界面测试，另通过 5 项翻页和专注滑动回归；浅深色沿用应用主题。测试书只导入模拟器并清理。laptop 远程 ADB 目前超时，本次新包尚未覆盖安装到个人手机。

## 调度、维护与边界

同步调度统一在 `app-core/sync/schedule.rs`，桌面与 Android 共用：阅读变更安静 10 秒后同步、连续变更最多延迟 60 秒、每 15 分钟完整检查；OCR、生成目录／元数据和 PDF 重排结果使用独立派生数据任务。普通失败从 30 秒开始指数退避，统计失败单独从 5 分钟开始重试；中国科技云等服务的限流期限由共享核心保留，手动同步也不会绕过限流。译文及 AI 排版缓存尚不属于云同步范围。

首次同步每批最多读取 8 份书籍清单，随即下载该批原书、恢复必要阅读状态并逐本入库，再处理下一批；OCR／PDF 等派生数据、云端封面及统计随后处理。复用已验证的不可变清单，避免新设备上传空阅读状态。阅读和派生数据各自保存按书断点，并校验远端相应版本；旧客户端缺少有效变更索引时保守重扫。中国科技云初始请求间隔为 0.5 秒，同一账号跨任务共用节流状态；429 后继续遵守服务端等待期限并自适应放慢，不重置既有的限流记录。

Android 收到实际入库事件后合并刷新书架，保留已有封面缓存；缺失封面补齐后再刷新对应显示。同步进度仅在云同步设置页显示，包括已就绪书籍数量、当前阶段和失败后的最早重试时间；书架首页不展示同步进度，即使中途限流，已入库书籍仍可见。

Android 通过 Rust 返回的下次检查／重试时间安排前台计时与系统后台唤醒，不在 Kotlin 重复判断任务类型、重试次数或全量间隔。调度快照、在途任务和派生数据变更标记持久化，进程回收后恢复；进程内继续使用单调时钟。同步采用进程级串行事务与原生书库锁；账户／配置变更取消旧请求、重置调度并丢弃过期结果。退出阅读后先落盘统计，再安排后台工作。WorkManager 周期任务最短 15 分钟并要求网络连接，实际执行受系统电量与后台限制影响，不保证精确时刻（[Android 调度说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)）。关闭同步时取消相关工作，不让未启用功能持续轮询。

更新逻辑从桌面提取至 `app-core/updates`，Android 根据 ABI 选择 `Torto-{version}-android-{abi}.apk`；GitHub 优先 Asset API，Gitee 的 ARM64 沿用 `torto-android-update.json`，x86_64 使用独立的 `torto-android-x86_64-update.json`，默认源自动回退。下载前验证来源、文件名及元数据，完成后核对大小／SHA-256；调用系统安装器前额外核对包名、版本号与本机签名。Debug／正式包互相隔离，正式覆盖升级需要同一正式证书签名的发布包。

Android 启动时先向 `rustls-platform-verifier` 注册 Application，再启动 HTTP 服务；JVM 验证器的 AAR 版本读取 Cargo.lock，R8 保留其 JNI 入口。不关闭证书验证；本地 HTTPS 回归确认自签名证书被拒绝，实际 GitHub 更新检查确认可信 HTTPS 可用。

诊断导出仅收集有限的运行／阅读／同步日志和设备版本，不打包书库、聊天、配置或凭据文件；进一步替换已存 API Key／WebDAV 密码及本机目录。每个共享报告使用独立文件，最多保留最近 3 份，FileProvider 只开放报告和更新缓存目录。构建时从实际 Cargo／Gradle 依赖及图标来源生成许可资源（当前 544 个组件），相同上游许可全文去重保存，支持离线查看及项目链接。

Android 调试构建显式内嵌公式字体，避免 RaTeX 读取编译主机路径；原生公式与识别公式均注册预览区域。对话和脚注使用共享 Markdown 规则与公式渲染器；可见消息在后台解析，流式更新合并延迟 120 ms，公式缓存 8 MiB，每条可见消息最多 24 个公式／8 MiB 位图，单个公式最大 1024×1024，超限或失败退回 LaTeX 文本。
